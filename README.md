# Telegram AI Family Expense Tracker

Telegram-бот для учёта семейных расходов. Пользователь может отправить
боту сообщение в свободной форме, например `кофе 350`, а ИИ помогает
определить сумму, категорию и другие данные расхода. Проект также
включает REST API и веб-интерфейс для просмотра и управления расходами.

## Возможности

-   Добавление расходов через Telegram в обычном текстовом сообщении.
-   Использование LLM для разбора сообщений и вызова инструментов
    приложения.
-   Работа с расходами и пользователями через бизнес-слой.
-   Хранение данных в PostgreSQL.
-   REST API и веб-интерфейс для работы с расходами.
-   Автоматизированные тесты для AI-, service- и transport-слоёв.
-   Запуск приложения и базы данных через Docker Compose.

> Доступные действия и ограничения зависят от текущей реализации бота и
> настроек окружения.

## Технологии

-   Go
-   Telegram Bot API
-   PostgreSQL
-   Docker и Docker Compose
-   LLM API с поддержкой chat completions и tool calling
-   HTML, CSS и JavaScript для веб-интерфейса

## Структура проекта

``` text
.
├── Dockerfile
├── docker-compose.yml
├── go.mod
├── go.sum
├── cmd/
│   └── server/
│       └── main.go
├── internal/

│   ├── config/             # Загрузка и проверка конфигурации
│   ├── domain/             # Доменные сущности, категории, фильтры и ошибки
│   ├── service/            # Бизнес-логика приложения
│   ├── storage/
│   │   └── postgres/       # Работа с PostgreSQL
│   └── transport/
│       ├── rest/            # REST API, DTO, middleware и веб-интерфейс
│       │   └── web/         # HTML, CSS и JavaScript веб-панели
│       └── telegram/        # Telegram-бот и обработчики сообщений
└── migrations/              # SQL-миграции и их embedding
```

### Назначение основных каталогов

-   `cmd/server` --- точка входа: создание зависимостей и запуск
    приложения.
-   `internal/ai` --- взаимодействие с LLM, системные инструкции,
    инструменты и агентный цикл.
-   `internal/config` --- чтение и валидация настроек приложения.
-   `internal/domain` --- основные сущности предметной области и
    доменные ошибки.
-   `internal/service` --- сценарии приложения и бизнес-правила.
-   `internal/storage/postgres` --- сохранение и чтение данных из
    PostgreSQL.
-   `internal/transport/telegram` --- получение сообщений из Telegram и
    отправка ответов.
-   `internal/transport/rest` --- HTTP-маршруты, обработка запросов и
    веб-панель.
-   `migrations` --- SQL-миграции структуры базы данных.

## Требования

Перед запуском установите:

-   [Git](https://git-scm.com/)
-   [Docker Desktop](https://www.docker.com/products/docker-desktop/) с
    работающим Docker Engine либо Docker Engine и Docker Compose на
    Linux
-   VPN, если без него в вашей сети недоступны Docker Registry или
    используемый LLM API

Для локального запуска без Docker дополнительно потребуется версия Go,
соответствующая директиве `go` в `go.mod`.

## Получение проекта

Клонируйте репозиторий:

``` bash
git clone https://github.com/highdolen/tgbot_task.git
cd tgbot_task
```

Если репозиторий опубликован под другим именем или в другом аккаунте,
замените URL на адрес своего репозитория.

## Настройка окружения

1.  Посмотрите, какие переменные конфигурации требуются приложению, в
    `internal/config/config.go` и `docker-compose.yml`.
2.  Создайте локальный файл `.env` в корне проекта и заполните его
    необходимыми значениями, используя `.env.example` как шаблон. 
3.  Укажите как минимум действительный токен Telegram-бота, ключ и
    параметры доступа к LLM API, а также настройки PostgreSQL, если они
    требуются текущей конфигурацией.


**Не угадывайте названия переменных окружения:** используйте точные
имена из `internal/config/config.go` и `docker-compose.yml`. Значения
для подключения к PostgreSQL внутри Docker Compose должны
соответствовать настройкам сервиса базы данных.

## Ограничение доступа к Telegram-боту

Для ограничения доступа к боту можно использовать переменную окружения ALLOWED_USER_IDS.

Если список задан, пользоваться Telegram-ботом смогут только пользователи с указанными Telegram ID.

Если список пустой, бот доступен любому пользователю Telegram, который найдёт его и напишет ему.

Пользователи, отсутствующие в заданном списке, не должны регистрироваться в базе данных или запускать обработку сообщений через LLM.

Для личного использования или разработки можно оставить список пустым. Если бот предназначен только для членов семьи, рекомендуется указать Telegram ID всех участников.

Чтобы узнать свой Telegram ID, можно воспользоваться ботом @userinfobot в Telegram. Перед использованием сторонних ботов для получения идентификатора учитывайте, что им может быть доступна информация о сообщениях, которые вы им отправляете.

Пример настройки:

# Ограничение доступа отключено
ALLOWED_USER_IDS=

# Пример ограничения доступа (формат списка смотрите в .env.example)
# ALLOWED_USER_IDS=123456789,987654321

Названия переменных и формат списка должны соответствовать реализации в internal/config/config.go.

Важно: пустой список не ограничивает использование бота и LLM API. 

## Важно: VPN и Docker

В сети, где доступ к Docker Registry или LLM-провайдеру ограничен,
**включите VPN до запуска Docker Desktop и проекта**. VPN также должен
обеспечивать доступ из контейнера к API выбранного LLM-провайдера.

Если Docker Desktop уже запущен, а контейнер не может подключиться к LLM
API, попробуйте перезапустить Docker Desktop после подключения VPN и
повторно запустить контейнеры. Работа VPN внутри Windows/WSL и внутри
Docker зависит от конкретного VPN-клиента и его маршрутизации, поэтому
сам факт подключения VPN не гарантирует, что контейнер использует его
соединение.

Проверить, что контейнеры запущены:

``` bash
docker compose ps
```

Посмотреть логи приложения:

``` bash
docker compose logs -f
```

Если в Compose несколько сервисов, при необходимости можно смотреть логи
конкретного сервиса:

``` bash
docker compose logs -f <имя-сервиса>
```

## Запуск через Docker Compose

Из корневой папки проекта выполните:

``` bash
docker compose up --build
```

Команда соберёт образы (если требуется) и запустит сервисы, описанные в
`docker-compose.yml`. При первом запуске Docker может скачать базовые
образы, поэтому нужен доступ к Docker Registry.

Чтобы запустить сервисы в фоне:

``` bash
docker compose up --build -d
```

Проверить состояние:

``` bash
docker compose ps
```

Посмотреть логи:

``` bash
docker compose logs -f
```

Остановить сервисы:

``` bash
docker compose down
```

Команда `docker compose down` обычно не удаляет данные в именованных
томах. Не добавляйте `-v`, если хотите сохранить данные PostgreSQL.

## Как проверить Telegram-бота

1.  Убедитесь, что Docker Compose поднял приложение и базу данных без
    ошибок.

2.  Откройте Telegram и найдите бота, для которого в `.env` указан
    токен.

3.  Отправьте `/start`

4.  Отправьте тестовое сообщение с расходом, например:

    ``` text
    кофе 350
    ```

5.  Проверьте ответ бота и убедитесь, что расход распознан и сохранён.
    Формат ответа зависит от текущей реализации и ответа LLM.

6.  Проверьте сценарии просмотра расходов и другие действия,
    реализованные в боте.

Если бот не отвечает, сначала посмотрите логи:

``` bash
docker compose logs -f
```

Проверьте токен Telegram, конфигурацию LLM, доступность API через VPN и
подключение к PostgreSQL.

## Проверка тестов и линтера

``` bash

```


``` bash
go vet ./...
```

Проверка линтером (если `golangci-lint` установлен):

``` bash

```

Если локальная версия Go старее версии, указанной в `go.mod`, тесты или
линтер могут завершиться ошибкой из-за несовместимости версий.

## Веб-интерфейс и REST API

После запуска приложения через Docker Compose откройте веб-интерфейс в браузере:

http://localhost:8080

В веб-панели можно управлять всеми семейными расходами: просматривать общий список, фильтровать расходы по членам семьи, периоду и категории, а также добавлять, редактировать и удалять записи.

В отличие от Telegram-бота, где каждый участник работает только со своими расходами, веб-панель предназначена для главы семьи и предоставляет доступ ко всем расходам семьи.

REST API обеспечивает взаимодействие веб-интерфейса с серверной частью приложения.

Если веб-интерфейс не открывается, проверьте, что контейнеры запущены:
``` bash
docker compose ps
```

Также проверьте логи приложения:
``` bash
docker compose logs -f
```


Если порт 8080 не указан или изменён в docker-compose.yml, используйте актуальный порт из конфигурации проекта.

## Остановка

Чтобы остановить контейнеры:

``` bash
docker compose down
```

Если нужно также удалить данные в томах, сначала убедитесь, что они
больше не нужны: команда `docker compose down -v` удаляет именованные
тома, включая возможные данные PostgreSQL.
